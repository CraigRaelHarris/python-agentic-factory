# API Design Skill

1. Start from actors/use cases and acceptance criteria.
2. Define request/response schemas before implementation.
3. Specify validation, error model, authentication/authorization and idempotency semantics.
4. Distinguish client errors from server/transient errors.
5. Avoid leaking internals in errors.
6. Document compatibility/versioning impact.
7. Add contract/acceptance tests around the boundary.
